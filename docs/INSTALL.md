# Установка cc-fleet с нуля — пошагово

cc-fleet — панель, которая держит несколько подписок Claude Code (и по желанию Codex и Notion AI) на **вашем** сервере: показывает лимиты,
сама переключает аккаунты, отвечает в Telegram и умеет передавать работу на второй сервер. Здесь всё, что нужно, чтобы поставить её
и подключить свои подписки, свой Telegram, по желанию второй сервер и голос. Ничего чужого в пакете нет: все адреса, имена и токены — ваши.

## Как читать эту инструкцию

- Каждый раздел — это **«Шаг N из M»**. Шаги идут по порядку: следующий опирается на предыдущий.
- После шага стоит **«Проверка»** — что именно вы должны увидеть. Не увидели — не идите дальше, смотрите таблицу **«Если не вышло»** в конце раздела.
- Установщик сам проверяет сделанное: перед каждым новым шагом он заново проверяет предыдущие. В любой момент можно спросить его, что готово: `sudo ./install.sh --check`.
- Любой шаг можно повторить: установщик безопасен к перезапуску и продолжает с места, где остановился.
- Всё, что помечено *(по желанию)*, можно пропустить и подключить позже.

## 1. Подготовка

Что нужно до того, как запускать установщик.

**Шаг 1 из 3 — сервер.** Свой сервер (VDS) с Ubuntu 22.04+ или Debian 12+, доступ **root**, свободно не меньше 1 ГБ (с голосом — 6 ГБ), выход в интернет.
Панель ходит на `api.anthropic.com` (читает лимиты аккаунтов) и на `api.github.com` (проверка обновлений; без него всё работает, кроме обновлений из панели).

**Шаг 2 из 3 — подписки и аккаунты** (нужны только те, что вы подключаете):

| Что | Зачем |
|---|---|
| 2 и больше подписок Claude Pro/Max | между ними панель переключает работу |
| Аккаунт Telegram | бот для уведомлений и ответов (создаётся у @BotFather, бесплатно) |
| Подписка ChatGPT Plus/Pro | Codex |
| Аккаунт Notion с Notion AI | Notion AI и его агенты |
| Второй сервер с root-доступом по ssh | куда передаётся работа, когда лимит кончился здесь |
| Домен с A-записью на сервер | панель на `https://ваш-домен/cc/` (без домена — см. шаг 9 установщика) |

**Шаг 3 из 3 — получить код.**

```bash
git clone https://github.com/r38dark/cc-fleet.git
cd cc-fleet
```

**Проверка:** `ls install.sh update_manifest.json cc_limits.py` показывает три файла.

| Что вижу | Причина и что делать |
|---|---|
| `git: command not found` | `apt-get install -y git`, либо скачайте архив релиза со страницы Releases и распакуйте |
| `Permission denied` при `./install.sh` | запускайте через `sudo ./install.sh` или `sudo bash install.sh` |

## 2. Установка одной командой

**Шаг 1 из 3 — запустить.**

```bash
sudo ./install.sh
```

Установщик задаст вопросы (в скобках — ответ по умолчанию; **Enter** = оставить), покажет план и **отдельным последним вопросом** спросит «Продолжить установку?» (он идёт после вопросов про хуки). Ничего не запишется, пока вы не ответите `y`.

Вопросы идут в порядке таблицы ниже. Часть вопросов пропускается: если на nginx ответили `n` — вопросов про домен, логин и пароль нет; если вместо домена вписали IP — нет вопроса про HTTPS и почту для сертификата; если Telegram `n` — нет вопросов про токен бота и chat_id. Пароль к панели установщик спрашивает один раз, без повторного ввода.

| Вопрос | Что отвечать |
|---|---|
| Имя screen-сессии, где живёт Claude Code | оставьте `claude` |
| Сколько аккаунтов Claude завести | сколько у вас подписок (по умолчанию 2): создаются пустые слоты, войдёте в них в разделе 3 |
| Порог авто-переключения, % | при каком заполнении 5-часового окна панель уводит работу на другой аккаунт (по умолчанию 85; обычно ставят 90) |
| Как к вам обращаться | имя подставляется в записки агентам |
| Часовой пояс | в нём показываются время сброса лимитов и записки (определяется сам; например `Europe/Moscow`) |
| Рабочая папка Claude Code | где Claude стартует (по умолчанию `/root`) |
| Открыть панель на своём домене с паролем (nginx) | `y` и домен — рекомендуется; `n` — только `127.0.0.1` (см. примечание ниже) |
| Домен, логин, пароль, HTTPS, почта для сертификата | домен уже должен указывать на сервер; HTTPS (Let's Encrypt) — `y`; вместо домена можно IP (HTTPS тогда не спрашивается) |
| Telegram | `y`, если создали бота (раздел 4); токен и chat_id спросит ниже |
| Установить Claude Code, если его нет | `y` (ставит Node.js 18+ и `npm install -g @anthropic-ai/claude-code`) |
| Codex | `y` — создаст отдельного пользователя ОС для Codex |
| Notion AI | `y` — поставит службы и браузер Chromium (~300 МБ) |
| Голос | `n`, пока не нужен (~5 ГБ места и 2 ГБ памяти; раздел 8) |
| Хук очереди входящих и стоп-кран инструментов | `y` (рекомендуется: они нужны для паузы по лимитам) |

> **Без домена.** Если ответить `n` на nginx, панель слушает только `127.0.0.1:8877`, а главная страница отдаётся лишь когда прокси прислал заголовок `X-Auth-User`:
> напрямую по SSH-туннелю браузер её не откроет (получите `403`). Если домена нет — в вопросе про домен впишите **IP сервера**: вопрос про HTTPS установщик тогда пропустит
> (для IP сертификат не выдаётся), и панель откроется на `http://IP/cc/` (логин и пароль идут открытым текстом — используйте только в доверенной сети;
> домен и HTTPS добавите позже: `sudo ./install.sh` с доменом или `certbot --nginx -d ваш-домен`).

Пример: все ответы одной строкой (панель на IP `203.0.113.5` с паролем, без Telegram, с Claude Code, Codex и Notion AI, без голоса, оба хука, подтверждение). Порядок — как в таблице:

```bash
printf '\n\n\n\n\n\ny\n203.0.113.5\nadmin\nВАШ_ПАРОЛЬ\nn\ny\ny\ny\nn\ny\ny\ny\n' | sudo ./install.sh
```

Шесть первых пустых строк — Enter на вопросы от имени screen-сессии до рабочей папки; дальше `y` (nginx), IP, логин, пароль, `n` (Telegram), `y` `y` `y` (Claude Code, Codex, Notion AI), `n` (голос), `y` `y` (хуки), `y` (подтверждение). Когда установщик запущен не из терминала, текст вопросов не виден — ориентируйтесь на таблицу или используйте вариант без вопросов (ниже, `CC_FLEET_YES=1`).

**Шаг 2 из 3 — дождаться 14 шагов.** Установщик печатает «Шаг N из 14» и после каждого ✅ или ❌ с подсказкой «Что делать». Перед очередным шагом он перепроверяет предыдущие. Во время шага 3 (пакеты) Ubuntu может сама перезапустить службы (сообщения `needrestart`, перезапуск `nginx`/`cc-limits`): это нормально, установка продолжается.

| № | Шаг | Что делает | Как понять, что прошёл |
|---|---|---|---|
| 1 | Проверка сервера | root, apt, Python 3.9+, место, доступ к GitHub и `api.anthropic.com` | ✅ «root, …, свободно N МБ» |
| 2 | Параметры установки | вопросы выше; ответы сохраняются (без паролей) | ✅ «ответы записаны» |
| 3 | Системные пакеты | python3-pyte, pexpect, screen, curl, openssl (+ nginx, certbot) | ✅ «python3, pyte, pexpect, screen, curl на месте» |
| 4 | Claude Code | ставит, если его нет | ✅ «Claude Code установлен: версия» |
| 5 | Файлы панели | копирует модули в `/opt/cc-limits`, сверяет с архивом | ✅ «все файлы на месте и целые» |
| 6 | Настройки и профили аккаунтов | `config.json` (права 600, случайный `hook_token`), пустые слоты `/root/.claude-profiles/accN` | ✅ «config.json записан» |
| 7 | Служба панели | systemd-служба `cc-limits`, порт 8877 | ✅ «панель отвечает на 127.0.0.1:8877» |

| 14 | Итог | адрес панели, список того, что осталось сделать руками | печатает «Установка завершена» |

**Шаг 3 из 3 — проверка.**

```bash
sudo ./install.sh --check
```

Ожидаемо: «✅ Шаг N из 14 — …» у каждого проверяемого шага (шагов 2 «Параметры установки» и 14 «Итог» в проверке нет — это вопросы и вывод итога, поэтому строк 12) и в конце «Всё в порядке». Откройте адрес из итога установки: должна загрузиться страница «Claude — лимиты аккаунтов» с карточками ваших слотов и блоком «Названия серверов».
Токен панели (`hook_token`) — секрет: он нужен для API, никому его не показывайте. Установщик его не печатает; он лежит в `/opt/cc-limits/config.json`, права 600.

Без вопросов (скрипты, CI): `CC_FLEET_YES=1 sudo -E ./install.sh`, значения — из переменных окружения:

| `CC_FLEET_SERVICE_NAME` | имя службы systemd | `cc-limits` |
| `CC_FLEET_PORT` | порт панели на 127.0.0.1 | `8877` |
| `CC_FLEET_SCREEN` | имя screen-сессии Claude | `claude` |
| `CC_FLEET_ACCOUNTS` | сколько слотов завести | `2` |
| `CC_FLEET_THRESHOLD` | порог авто-переключения, % | `85` |
| `CC_FLEET_OWNER` | как к вам обращаться | `владелец` |
| `CC_FLEET_TZ` | часовой пояс (IANA) | пояс сервера |
| `CC_FLEET_WORKDIR` | рабочая папка Claude Code | `/root` |
| `CC_FLEET_NGINX`, `CC_FLEET_DOMAIN`, `CC_FLEET_BASIC_USER`, `CC_FLEET_BASIC_PASS` | nginx, домен, логин, пароль | выключено |
| `CC_FLEET_HTTPS`, `CC_FLEET_CERT_EMAIL` | HTTPS и почта для сертификата | выключено |
| `CC_FLEET_TG`, `CC_FLEET_BOT_TOKEN`, `CC_FLEET_CHAT_ID` | Telegram | выключено |
| `CC_FLEET_TG_ENV` | файл с токеном бота плагина Claude | `/root/.claude/channels/telegram/.env` |
| `CC_FLEET_CLAUDE` | ставить Claude Code, если его нет | `y` |
| `CC_FLEET_CODEX`, `CC_FLEET_CODEX_USER` | Codex и имя пользователя ОС для него | `y`, `codex` |
| `CC_FLEET_NOTION` | службы Notion AI | `n` |
| `CC_FLEET_VOICE` | голос | `n` |
| `CC_FLEET_HOOK_QUEUE`, `CC_FLEET_HOOK_TOOLS` | хуки Claude Code | `y` |
| `CC_FLEET_CLAUDE_SETTINGS` | путь к `settings.json` Claude Code | `~/.claude/settings.json` |

| Что вижу | Причина и что делать |
|---|---|
| ❌ «нужны права root» | `sudo ./install.sh` |
| ❌ «нужен Debian/Ubuntu» | установщик рассчитан на `apt`; на другой системе поставьте пакеты шага 3 вручную и скопируйте файлы по `update_manifest.json` |
| ❌ «на диске меньше 1 ГБ» | освободите место |
| ⚠️ «api.anthropic.com не отвечает» | с сервера закрыт выход в интернет: без него лимиты аккаунтов не читаются; откройте исходящий HTTPS |
| ❌ шаг 3: «не удалось поставить пакеты» | чаще всего занят dpkg (`apt` уже запущен): подождите и повторите; ошибка — выше в выводе |
| ⚠️ шаг 4: Claude Code не установился | нужен Node.js 18+ с `deb.nodesource.com`; вручную: `apt-get install -y nodejs npm` (на Ubuntu 22.04 версия старая — поставьте Node 20 из NodeSource), затем `npm install -g @anthropic-ai/claude-code`, `claude --version` |
| ❌ шаг 7: «служба не ответила» | `journalctl -u cc-limits -n 50 --no-pager` — там причина (занят порт 8877? поменяйте `CC_FLEET_PORT`) |
| ⚠️ шаг 9: «сертификат не получен» | домен ещё не указывает на сервер или закрыт порт 80; панель работает по `http`; исправьте и выполните `certbot --nginx -d домен -m почта --agree-tos --redirect` |
| ❌ шаг 10: «Telegram не принял токен» | токен — у @BotFather (`/mybots` → бот → API Token), вид `123456789:AAH…`, целиком |
| ❌ шаг 10: «chat_id не определён» | отправьте боту любое сообщение (в Telegram нажмите **Start**) и запустите установщик снова, либо задайте `CC_FLEET_CHAT_ID` |

## 3. Аккаунты Claude

Цель: панель видит ваши аккаунты, а Claude Code работает под активным из них.

**Шаг 1 из 3 — открыть панель.** Адрес — из итога установки (`https://ваш-домен/cc/`, логин и пароль — те, что вы задали на шаге 9).
Вверху должен быть список слотов (`acc1`, `acc2`…), сейчас они пустые.

**Проверка:** страница открывается, ошибок нет; в «Общие настройки» (шестерёнка) виден блок «Названия серверов».

**Шаг 2 из 3 — войти в каждый аккаунт.** Нажмите «Добавить аккаунт» (или «Войти заново» в меню ⋯ карточки уже заведённого слота), при желании впишите почту (подставится на странице входа) и нажмите **«Получить ссылку для входа»**.
Откройте ссылку **в браузере, где вы вошли в нужный аккаунт Claude**, скопируйте код со страницы и вставьте в окно панели. Аккаунт встаёт в ротацию. Повторите для каждого аккаунта.
Пароль в панель вводить не нужно, токены хранятся только на вашем сервере (`/root/.claude-profiles/accN/`).

Если панель ещё недоступна, можно вручную: в сессии Claude Code `/login`, затем в обычной оболочке `cc-switch save 1` (для второго — `/login` под другим аккаунтом и `cc-switch save 2`); проверить: `cc-switch list`.

**Проверка:** у каждой карточки видны почта, план (Pro/Max), «Сессия 5ч» и «Неделя» с процентами; один аккаунт помечен «Выбран».

**Шаг 3 из 3 — запустить Claude Code и задать пороги.**

```bash
/opt/cc-limits/start_claude.sh
```

Скрипт запускает Claude Code в screen-сессии (с каналом Telegram, если плагин настроен); панель сама запускает его при смене профиля и возврате работы.
Хуки из шага 8 установщика Claude Code читает при старте: если сессия уже была запущена до установки — перезапустите её.
В «⚙ Настройки Claude» → «Переключение и лимиты» задайте пороги (обычно сессия 90 %, неделя 99 %), нажмите «Сохранить» и включите «Авто-переключение».
«Пауза на недельном потолке» — если не хотите сжечь неделю, когда переключаться уже некуда.

**Проверка:** `screen -ls` показывает сессию `claude`; вкладка «Claude» в консоли панели показывает работающий Claude Code.

| Что вижу | Причина и что делать |
|---|---|
| Страница отвечает `403` | прокси не прислал `X-Auth-User`: открывайте адрес через nginx из шага 9 (прямой порт 8877 страницу не отдаёт) |
| «Войти»: код не принимается | код живёт недолго: нажмите «Получить ссылку для входа» заново и войдите в тот же аккаунт |
| На карточке «Время не получено» | аккаунт ещё не опрошен (до 2 минут) или нет выхода на `api.anthropic.com` |
| `screen -ls` пуст | `claude --version` (установлен ли Claude Code?), затем `/opt/cc-limits/start_claude.sh`; в `config.json` проверьте `screen_session` и `work_dir` |
| «Claude не запускаю: профиль Notion AI включён» / «работа на втором сервере» | это не ошибка: выключите профиль Notion AI в шапке или верните работу на этот сервер |

## 4. Telegram

*(по желанию)* Цель: уведомления панели (переключения, паузы) и разговор с Claude из Telegram. Один бот и один чат — общие для Claude и Notion AI; у Codex свой бот (раздел 5).

**Шаг 1 из 6 — создать бота.** В Telegram откройте @BotFather → `/newbot` → имя и адрес бота (оканчивается на `bot`). BotFather пришлёт токен вида `123456789:AAH…` — копируйте целиком.
Токен — секрет: любой, у кого он есть, управляет ботом.

**Проверка:** токен у вас в буфере; `curl -s https://api.telegram.org/bot<ТОКЕН>/getMe` отвечает `"ok":true`.

**Шаг 2 из 6 — подключить к панели.** Если вы ответили `y` на вопрос про Telegram, установщик уже спросил токен и chat_id (шаг 10) и отправил тест. Иначе запустите `sudo ./install.sh` ещё раз и ответьте `y`
(или `CC_FLEET_TG=y CC_FLEET_BOT_TOKEN=… sudo -E ./install.sh`). Установщик сам определит ваш chat_id: откройте бота в Telegram, нажмите **Start**, отправьте «привет» — он увидит сообщение.

**Проверка:** в Telegram пришло «✅ cc-fleet установлен…»; в `/opt/cc-limits/config.json` есть `chat_id`.

**Шаг 3 из 6 — поставить плагин Telegram для Claude Code** *(чтобы писать Claude из Telegram)*. Плагину нужен [Bun](https://bun.sh): `curl -fsSL https://bun.sh/install | bash`.
В консоли Claude (вкладка «Claude» или `screen -r claude`):

```
/plugin install telegram@claude-plugins-official
/telegram:configure 123456789:AAH…
```

Токен сохранится в `/root/.claude/channels/telegram/.env`. Установщик (шаг 10) и панель берут токен оттуда же.

**Шаг 4 из 6 — перезапустить Claude с каналом.** `/opt/cc-limits/start_claude.sh` добавляет `--channels plugin:telegram@claude-plugins-official` сам, когда файл `.env` есть.
Перезапустите сессию Claude (закройте её и запустите скрипт заново).

**Шаг 5 из 6 — спарить свой аккаунт.** Напишите боту в Telegram: он ответит кодом из 6 знаков. В консоли Claude: `/telegram:access pair <код>`.

**Шаг 6 из 6 — закрыть доступ чужим.** В консоли Claude: `/telegram:access policy allowlist` — бот перестанет отвечать незнакомым.

**Проверка:** напишите боту «привет» — ответит Claude; уведомления панели приходят в тот же чат.

| Что вижу | Причина и что делать |
|---|---|
| Бот молчит | Claude запущен без `--channels` (перезапустите через `start_claude.sh`); не нажат **Start**; не спарены (шаг 5); плагин не поставлен (шаг 3) |
| «Telegram не принял токен» (шаг 10 установщика) | токен скопирован не целиком или бот удалён: возьмите новый у @BotFather |
| Тест пришёл, а Claude не отвечает | это разные вещи: тест шлёт панель, а ответы Claude идут через плагин (шаги 3–5) |
| «Бот не смог написать в чат» | не нажат **Start** или неверный chat_id: узнать свой id можно у @userinfobot |
| Два процесса «воюют» за бота (`409 Conflict`) | один бот одновременно читает только один процесс: не подключайте тот же токен к Codex или другому балансеру |

## 6. Notion AI и агенты Notion

*(по желанию)* Notion AI — третий агент: живёт в постоянном чате Notion, получает сообщения из Telegram и из вкладки «Notion AI» в консоли, отвечает в Telegram (текст и голос) и работает на вашем сервере по SSH.
Кроме главного агента можно создавать **своих агентов** (например, по проекту), у каждого — свой SSH-ключ и свой чат в Telegram. Нужен аккаунт Notion с Notion AI.

**Проще всего — мастер в панели:** серая плитка «Notion AI» (или ⚙ → Notion AI → «Мастер подключения по шагам») → «Подключить Notion AI». Он проведёт по шагам 1–7 ниже, у каждого есть проверка; шаг 1 он делает сам.

**Шаг 1 из 7 — поставить службы.** Если на вопрос про Notion AI вы ответили `y`, установщик сделал это на шаге 12. Иначе нажмите «Установить службы» в мастере или выполните: `sudo bash /opt/cc-limits/notion_ai/install.sh` (ставит Playwright с Chromium, службы `notion-delegate`, `notion-ai-view`, `notion-ai-tg`, команды `notion-ai-reply`, `notion-ai-mode`, `notion-ai-step`).
**Проверка:** `systemctl is-active notion-delegate notion-ai-view` — оба `active`.

**Шаг 2 из 7 — ссылка на постоянный чат.** В Notion откройте Notion AI, начните новый чат и скопируйте его адрес (`https://app.notion.com/chat?t=…`). В панели: ⚙ Общие настройки → Notion AI → «Ссылка на постоянный чат» → «Сохранить».
**Проверка:** «Проверить связь» показывает «Ссылка на чат» ✓.

**Шаг 3 из 7 — вход в Notion.** Там же впишите почту входа, «Сохранить», нажмите «Войти» в строке «Вход в Notion»: на почту придёт код — введите его там же. Не больше 3 входов в сутки.
**Проверка:** «Вход в Notion на сервере» — «подключён».

**Шаг 4 из 7 — токен Notion API** *(нужен, чтобы видеть и создавать других агентов; главный агент работает и без него)*. Создайте внутреннюю интеграцию на `notion.so/profile/integrations`, скопируйте её секрет (начинается с `ntn_`) и вставьте в «Токен Notion API» → «Сохранить».
Токен сохраняется в отдельный файл с правами 600 и в панели больше не показывается.
**Проверка:** «Проверить связь» → «Токен Notion API: работает, агентов: N». Если там «401» — токен неверный; «403» — у интеграции нет нужных прав (откройте её настройки).

**Шаг 5 из 7 — ключ доступа и инструкция для главного агента.** Попросите Notion AI создать SSH-ключ и вставьте публичную часть (одну строку `ssh-ed25519 AAAA…`) в «Ключ доступа к серверу (SSH)».
Затем скопируйте текст из блока «Инструкция для постоянного чата» и отправьте его первым сообщением в чат — так агент узнает, откуда приходят сообщения и куда отвечать.
**Проверка:** в списке ключей есть строка с меткой `ccfleet-notion-ai`.

**Шаг 6 из 7 — проверить связь и включить.** «Проверить связь» ничего не отправляет ни в чат, ни в Telegram. Затем в шапке выберите Notion AI → «Notion AI · только он»: на это время Claude останавливается, и общий бот слушает Notion AI.
**Проверка:** сообщение боту «привет» из Telegram приходит агенту, ответ возвращается в Telegram.

**Шаг 7 из 7 — свои агенты.** В плитке Notion AI → «＋ Новый агент»: имя, модель, effort; галка «Доступ к серверу»; «Куда отвечать в Telegram» — основной канал или другой чат (id), кнопка «Проверить Telegram» присылает тест. «Создать» — и дальше всё идёт само, около 3,5 минут:
строка под проектом показывает этап, полосу и «осталось ~N мин» (время считается по прошлым созданиям). Окно создания закрывается сразу.

Что панель делает сама: создаёт агента из шаблона, задаёт имя, модель, effort, интернет и инструкции, **выдаёт ему постоянный SSH-ключ** (публичная часть — в `authorized_keys`, приватная — в инструкцию агента: его «компьютер» в Notion пересоздаётся между сообщениями,
поэтому свой ключ он не сохранит), называет чат и **проверяет, что агент зашёл на сервер** (по журналу `sshd`). Не зашёл — красная строка «агент создан, но на сервер по ключу не зашёл: причина», а не тихое «готово».
Ответы агента в Telegram идут с пометкой «[имя агента]» в начале.

В окне агента (клик по его строке): состояние доступа и «Новый ключ SSH»; «Telegram: куда отвечает агент» (+ «Проверить», «Сохранить»); «Принимает сообщения из Telegram» (пока включён профиль Notion AI — кому идут ваши сообщения);
имя, модель, effort, «Открыть консоль», «Удалить агента». Удаление убирает агента в Корзину Notion (30 дней), его ключ из `authorized_keys` и файл ключа.

> **Безопасность.** Агент с доступом к серверу — это **root по SSH**. Приватный ключ хранится в инструкции агента в Notion — тот, кто может открыть агента в вашем Notion, может войти на сервер.
> Не добавляйте в рабочее пространство посторонних; «Новый ключ SSH» отзывает прежний; агентам, которым сервер не нужен, галку «Доступ к серверу» не ставьте.

**Проверка:** новый агент в списке, у него вкладка в консоли; в окне агента «✓ ключ выдан, вход проверен».

| Что вижу | Причина и что делать |
|---|---|
| «Сервис Notion (notion-delegate) не отвечает» | `systemctl status notion-delegate`, `journalctl -u notion-delegate -n 50 --no-pager` |
| «Вход в Notion на сервере — слетел» | войдите заново (шаг 3); не больше 3 входов в сутки |
| «⚠ нет связи с Notion» в списке агентов | не задан или неверен токен Notion API (шаг 4) |
| «не знаю адрес сервера для SSH агента» | впишите адрес в «Адрес сервера для SSH агентов» (⚙ → Notion AI): домен или IP, по которому агент зайдёт; пусто — внешний IP сервера |
| «агент создан, но на сервер по ключу не зашёл» | порт 22 закрыт для адресов Notion или неверен адрес сервера; откройте исходящие подключения агента (ssh с любых адресов) и нажмите «Новый ключ SSH» |
| «Notion не опубликовал изменения агента» | кнопка Save в настройках агента не сработала: повторите действие |
| Агент не отвечает в Telegram | профиль Notion AI не включён (шаг 6), либо агент не выбран в «Принимает сообщения из Telegram» |
| «Тест» в Telegram: «chat not found» | бот не добавлен в этот чат (в канале — администратором) или неверен id |

## 7. Второй сервер

*(по желанию)* Второй сервер — машина с вашим вторым аккаунтом Claude, на которую панель передаёт работу, когда лимит кончился здесь (и обратно). Примеры: «Claude A» — этот сервер, «Claude B» — второй
(подписи меняются в «Общие настройки» → «Названия серверов»).

Пока второй сервер не подключён, «Claude B» и всё, что с ним связано (вкладка консоли, плашка в шапке, карточка, кнопки передачи работы), в панели скрыты — на чистой установке их нет.

Что нужно на втором сервере: Linux с root-доступом по ssh, установленный Claude Code (`/usr/bin/claude`), аккаунт Claude, под которым он будет работать. Остальное мастер проверит и доустановит сам.

В панели: ⚙ Общие настройки → **«Второй сервер»**. Мастер состоит из трёх шагов, прямо на странице написано «Шаг N из 3»; кнопка «Подключить» закрыта, пока проверка не пройдена.

**Шаг 1 из 3 — ключ панели.** Мастер показывает команду `echo 'ssh-ed25519 … cc-fleet-panel' >> /root/.ssh/authorized_keys` (кнопка «Скопировать команду»). Выполните её на втором сервере под root.
**Проверка:** с этого сервера `ssh -i /opt/cc-limits/remote_key root@адрес-второго true` не спрашивает пароль.

**Шаг 2 из 3 — адрес и проверка.** Впишите адрес (IP или имя), порт ssh (22), адрес этого сервера для второго (подставляется сам), имя сессии tmux (по умолчанию `ccfleet`) → **«Проверить»**. Мастер показывает список:

| Строка | Что значит | Если ❌ |
|---|---|---|
| На этом сервере есть ssh, ssh-keygen, rsync | инструменты здесь | `apt-get install -y openssh-client rsync` |
| Вход по ssh | панель вошла на второй сервер по ключу | шаг 1; проверьте адрес и порт; на втором — `PermitRootLogin prohibit-password` или `yes` |
| Вход под root | вход именно под root | добавьте ключ в `/root/.ssh/authorized_keys` |
| Установлен python3, tmux, rsync | нужны для работы | кнопка **«Установить недостающее»** (apt-get на втором сервере) |
| Claude Code (`/usr/bin/claude`) | на втором сервере есть Claude | поставьте Claude Code; если он в другом месте — `ln -sf <путь> /usr/bin/claude` |
| Вход Claude на втором сервере ⚠ | не обязателен сейчас | после подключения — «Войти заново» на карточке второго сервера |
| Telegram-плагин Claude ⚠ | нужен, чтобы Claude на втором отвечал в Telegram | раздел 4, шаги 3–6 на втором сервере |

**Проверка:** «Готово к подключению»; кнопка «Подключить» стала доступной.

**Шаг 3 из 3 — подключить.** «Подключить»: мастер кладёт на второй сервер `ctl.py` и `usage.py`, создаёт там ключ обратного ssh, добавляет его в `authorized_keys` **этого** сервера с ограничением (`from=<адрес второго>`, без терминала и пересылок), проверяет обратный доступ и записывает пару в `remote_members.json`.
Не получился обратный доступ — ключ на этом сервере не остаётся и ничего не записывается. «Отключить» убирает пару и ключ обратного входа (на втором сервере ничего не удаляется).
**Проверка:** блок показывает «Подключён: адрес…»; на панели появилась карточка второго сервера; у кнопки передачи работы («Передать работу в …») есть второй сервер. Повторное «Подключить» ничего не дублирует.

Дальше: на карточке второго сервера «Войти заново» (ссылка и код, токен остаётся там); в окне агента Claude переключатель **«Включить авто»** — при заданном проценте лимита работа сама переходит на второй аккаунт;
«Изменить порог» в этом окне открывает «Настройки Claude». Если на втором сервере Claude отвечает без пауз и лимит исчерпан, через 2 минуты панель останавливает его и переключает принудительно.

| Что вижу | Причина и что делать |
|---|---|
| «Второй сервер не достучался сюда по адресу…» | второй сервер не видит этот по адресу из поля «Адрес этого сервера» (порт 22): впишите правильный адрес или откройте порт |
| «Нет входа по ssh» | ключ панели не добавлен или неверны адрес/порт |
| «apt-get не справился» | на втором сервере нет интернета или занят dpkg; поставьте пакеты вручную |
| Работа не передаётся | у карточки второго сервера нет входа Claude: «Войти заново» |

## 8. Голос

*(по желанию)* Локальная озвучка ответов (Silero, русский) и расшифровка голосовых сообщений из Telegram (Whisper small). Без ключей и внешних сервисов, всё на вашем сервере. Нужно **~5 ГБ места и 2 ГБ памяти**.

**Шаг 1 из 2 — установить.** Ответьте `y` на вопрос про голос (шаг 13 установщика) или выполните `sudo bash voice/install.sh`. Установка идёт по шагам «Голос · шаг N из 8», 5–15 минут при первой загрузке моделей:
проверка сервера → пакеты → два окружения Python → файлы и команды → модели и служба → **проверка озвучки** (озвучивается тестовая фраза) → **проверка расшифровки** (та же фраза расшифровывается обратно).
**Проверка:** в конце «Голос установлен», `curl http://127.0.0.1:8879/health` отвечает `ok`; `sudo bash voice/install.sh --check` — все восемь шагов ✅.

**Шаг 2 из 2 — включить в панели.** Установщик голоса сам включает галку «Голосовые ответы в Telegram» (⚙ Общие настройки → Notion AI), если настройки Notion AI уже есть; иначе включите её там вручную. Агент Notion отвечает в Telegram текстом и голосом (`notion-ai-reply`), голосовые из Telegram расшифровываются в текст.
**Проверка:** «Проверить связь» → «Голос: включён».

Команды: `ccfleet-say "текст" файл.ogg [голос]` (голоса: `kseniya`, `aidar`, `baya`, `xenia`, `eugene`), `ccfleet-say-long файл.txt файл.ogg`, `ccfleet-transcribe файл.oga`.
Убрать голос: `sudo bash voice/install.sh --remove` (панель продолжит работать текстом). Подробности, лицензии моделей — `voice/README.md`.

| Что вижу | Причина и что делать |
|---|---|
| «нет доступа к … » на шаге 1 | закрыт выход в интернет (PyTorch, PyPI, Hugging Face, GitHub нужны на время установки) |
| «мало места» / «мало памяти» | освободите место (или `CCFLEET_VOICE_DIR=/другой/каталог`); при памяти меньше 2 ГБ голос не ставьте |
| «модели озвучки не загрузились» | см. `/opt/ccfleet-voice/preload.err`; после исправления запустите снова (следы обрыва установщик чистит сам) |
| `ccfleet-say: голос не получился (HTTP 000)` | служба не запущена: `systemctl restart ccfleet-tts` |

## 9. Проверка, обновление, удаление, секреты

**Проверка в любой момент.** `sudo ./install.sh --check` — состояние всех 14 шагов. В панели: «Проверить связь» у Notion AI; у Codex и второго сервера — свои проверки. Журнал панели: `journalctl -u cc-limits -n 100 --no-pager`.

**Обновление.** Раз в 6 часов панель делает один запрос к GitHub (без токена). Нашёлся релиз новее — вверху баннер: «Обновить» (по умолчанию вручную; в «⚙ Настройки → Обновления» можно включить автоматическое).
Обновление скачивается только с GitHub, проверяется и ставится с резервной копией; при неудаче откатывается. Вручную: `git pull && sudo ./install.sh` — установщик обновит файлы и не тронет ваши токены и настройки.

**Удаление.** Остановите и уберите службы: `systemctl disable --now cc-limits notion-delegate notion-ai-view notion-ai-tg ccfleet-tts` (те, что есть), удалите `/etc/systemd/system/<служба>.service`, `/etc/cron.d/cc-limits-pause`, `/etc/nginx/sites-enabled/<домен>`,
затем `/opt/cc-limits` (**там токены аккаунтов в `profiles` и `config.json`**), `/root/.claude-profiles`, `/root/notion_web`, `/opt/ccfleet-voice`. Хуки удалите из `~/.claude/settings.json` (ищите `queue_on_limits.py`, `pause_tool_gate.py`).
Агентов Notion удаляйте из панели **до** этого (кнопка «Удалить агента» убирает их ключи из `authorized_keys`); аккаунты Codex — «удалить целиком» в мастере Codex.

**Где лежат секреты** (все файлы — только root):

| Что | Где |
|---|---|
| Токен панели `hook_token`, `chat_id`, токен запасного бота | `/opt/cc-limits/config.json` (600) |
| Вход в аккаунты Claude | `/root/.claude-profiles/accN/` |
| Токен бота Claude | `/root/.claude/channels/telegram/.env` |
| Вход в Notion и токен локального API | `/root/notion_web/state.json`, `/root/notion_web/api_token` |
| Токен Notion API | `/root/notion_web/notion_pat` (600) |
| Приватные ключи агентов Notion | `/root/notion_web/agent_keys/<id>.key` (600) и инструкция агента в Notion |
| Бот Codex | настройки моста Codex в панели |
| Ключ панели для второго сервера | `/opt/cc-limits/remote_key` |

Не публикуйте эти файлы и не присылайте их в чаты. Панель никуда не отправляет токены аккаунтов.

## Приложение А. Второй независимый балансер на другом компьютере

Пример: основной балансер на одном сервере, а на другом компьютере — свой, для отдельного проекта (например, торговли) со своим Claude и своим агентом Notion; они между собой не общаются, и сообщения не смешиваются.
Это **не** «второй сервер» из раздела 7 (тот работает под управлением одного балансера); здесь второй балансер ставится целиком.

**Шаг 1 из 4 — установить балансер на втором компьютере** по разделам 1–3. Всё (токены, профили, настройки) на нём своё.

**Шаг 2 из 4 — отдельный Telegram-бот.** Создайте у @BotFather **нового** бота под этот балансер (раздел 4): один бот одновременно читает только один процесс, поэтому тот же токен на двух балансерах не подключается (`409 Conflict`). Так сообщения проекта идут в отдельный чат.

**Шаг 3 из 4 — Notion AI.** Раздел 6 на втором компьютере. Можно использовать тот же аккаунт Notion и ту же интеграцию (токен): список агентов берётся из всего рабочего пространства, поэтому на каждом балансере видны агенты обоих; свой проект ведёт свой агент.
Создайте агента проекта кнопкой «＋ Новый агент»: у него будет свой SSH-ключ **на этот компьютер** и «Куда отвечать в Telegram» — чат бота этого балансера.

**Шаг 4 из 4 — проверка.** Напишите боту проекта — отвечает Claude этого компьютера; включите профиль Notion AI и выберите агента проекта в его окне («Принимает сообщения из Telegram») — отвечает он, с пометкой «[имя агента]».
**Проверка:** сообщения проекта приходят только в чат проекта, основной балансер их не видит.
