# Общий выбор рабочего сценария

Обе модели показаны в одном окне. Роли Full, Оркестратор, Исполнитель и резерв с Notion являются черновиком до «Применить сценарий». Поиск, отдельные вкладки провайдеров и прежний подвал со счётчиком/Escape удалены.

Допустимы только шесть полных сочетаний: Full одной модели; резерв одной модели; Claude-оркестратор + Codex-исполнитель; Codex-оркестратор + Claude-исполнитель. Неактивная сторона у Full/резерва при применении ставится на паузу. Нажатие карточки не назначает другую роль автоматически. Несовместимые роли показываются с причиной блокировки. Повторное нажатие снимает выбранную роль. Неполная пара и устаревший черновик не применяются.

GET /api/profiles возвращает capabilities.manual_scenario, manual_scenario.choices и revision. POST /api/profiles/scenario/apply принимает choices для обеих моделей и целочисленную revision; Full/резерв также требуют confirm. Проверка выполняется до побочных эффектов, затем существующий NativeProfiles применяет обе стороны одной транзакцией с восстановлением состояния и сессий при отказе. Исполнитель получает workspace-write, ведущая — чтение проекта и папку обмена; подтверждение шагов человеком и предел «дев» сохранены.

Старые сессии при установке продолжают работать. Для прежнего несогласованного состояния manual_scenario.legacy=true: новый черновик пуст, текущие роли/права показываются в основных плитках. Установка и чтение API не применяют новый сценарий, не перезапускают и не ставят на паузу модели. Применение начинается только после явного законченного выбора и общей кнопки. Во время установочной проверки временно удерживаются только переключения сценария; ввод в текущую консоль доступен. Метка проверки привязана к PID и времени старта установщика, без таймера профилей.

Резерв с Notion не имеет срока и восстанавливает весь предыдущий сценарий при выключении. Автоматический резерв остаётся отдельной явно включаемой настройкой. Сохранение общего Notion-агента использует прежние поля и обработчик; черновики полей не теряются при опросе.

Проверки: матрица всех сочетаний, валидация ревизии и сохранённой топологии, миграция без эффектов, обе стороны транзакции, rollback, busy/preflight, подтверждения, резерв/восстановление, шлюзы инструментов и HTTP-маршрут. Браузер использует настоящие GET-снимки панели; POST сценариев идут только в изолированный NativeProfiles со stub-адаптером консолей. Реальные консоли при этих проверках не переключаются. Геометрия проверена на ПК до1024×576 и в мобильном touch-окружении; текущая нативная беседа, модель, effort и cwd контролируются при установке.
