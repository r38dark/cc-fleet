# Выбор профиля Full

По последнему указанию Дениса доступны только два рабочих варианта: Claude Full и Codex Full. Оркестратор и исполнитель убраны из общего окна, публичных каталогов и новых запросов применения. Общий выбор одной модели, подтверждение Full и одна кнопка «Применить профиль» сохраняются. Нажатие второй Full-карточки переносит черновой выбор на неё; текущие консоли до применения не меняются.

Выбранная карточка имеет контрастную цветную рамку, заливку, галочку и подпись «Выбран». Claude использует тёплый акцент, Codex — мятный. Окно компактно на ПК; на мобильном оно открывается сверху с отдельной прокруткой и блокировкой фона.

POST /api/profiles/scenario/apply по-прежнему принимает обе choices и revision. Новый рабочий выбор допускает только Full одной модели; профиль другой стороны ставится на паузу при явном применении. Выбор пары оркестратор/исполнитель отклоняется до побочных эффектов. Публичные каталоги обычных профилей, включая прежний bridge-каталог, показывают только Full.

Оперативный резерв и общие настройки Notion остаются отдельными служебными контролами, вне обычного выбора профиля. Резерв не имеет срока. Старые сохранённые пары читаются и восстанавливаются как историческое состояние, без автоматического перевода их прав в Full. Приватные описания нужны для совместимости; выбрать их заново через API нельзя.

Установка и GET не переключают сессии. Применение использует существующую NativeProfiles-транзакцию с проверкой ревизии, busy/preflight, сохранением thread/model/effort и rollback. Установочный контроль удерживает только переключение профилей по PID/start установщика и сохраняет ввод в текущую консоль.

Проверки: только Full в публичных каталогах, отклонение удалённых ролей, чтение исторического состояния, Full-исключение, резерв/восстановление, транзакции и откат; браузерные проверки используют реальные GET-снимки и изолированные профильные POST без переключения живых консолей.
