# ⚡ cc-fleet

🇷🇺 Русский · [🇬🇧 English](README.en.md)

**Self-host дашборд для ротации нескольких аккаунтов Claude Code по лимитам.**

Мониторит лимиты (5 часов / неделя) сразу нескольких Pro/Max-аккаунтов на
одной VDS, автоматически переключает активную сессию по достижении порога и
показывает live-зеркало консоли работающего Claude Code — всё в одной
веб-панели, без сторонних сервисов и облаков.

А когда переключаться уже некуда — ставит работу на паузу и сам снимает её,
как только ближайшее окно сбросится.

## Возможности

- 📊 **Мониторинг лимитов** нескольких аккаунтов сразу — 5-часовое окно и
  недельная квота, с обратным отсчётом до сброса.
- 🔁 **Авто-переключение** активного аккаунта по настраиваемому порогу
  заполнения сессии (галочка в панели, порог — ползунок/поле).
- 🎯 **Режим оптимизации лимитов** — сервис сам решает, каким аккаунтом
  пользоваться прямо сейчас, чтобы растянуть суммарный лимит по всем
  аккаунтам; ручные кнопки переключения на время его работы блокируются.
  Плановое переключение (v1.19.3) ждёт паузы между ходами живой сессии — не
  дольше 15 минут (`opt_defer_max_sec`, 0 — не ждать): смена аккаунта посреди
  хода сбрасывает кэш промпта, а у Sonnet 5.5 ещё и рассуждения этого хода.
  Аварийные уходы (порог сессии, неделя, слёт в Free) — сразу, как и раньше.
- 🖥 **Live-зеркало консоли** — та же `screen`-сессия, что видна в терминале,
  транслируется в браузер в реальном времени (только чтение).
- 🚦 **Гейт для фоновых задач** (`limits_gate.py`) — одна строка в чужом
  скрипте, и cron-прогоны/вотчеры не стартуют, пока активный аккаунт уже
  выбрал окно: иначе они добивают именно тот лимит, который нужен тебе.
- ⏸ **Пауза по лимитам с будильником** (`pause_ctl.py`) — когда все аккаунты
  выше порога 5-часового окна и переключаться некуда, работа встаёт на паузу,
  а системный cron сам снимает её на ближайшем сбросе окна и будит живую
  сессию. Недельный потолок ставит паузу, только если включить «Пауза на
  недельном потолке» (v1.21.0). Ничего не живёт внутри самой
  сессии Claude Code, поэтому пауза переживает перезапуск, `/clear` и ребут.
- ▶️ **Кнопка «Отключить паузу»** в баннере панели — работать сверх порога,
  когда очень надо; «Включить паузу» ставит её обратно, а если не нажать —
  пауза включится сама, как только окно отпустит.
- 🛑 **Стоп-кран инструментов** (хук `PreToolUse`) — встала пауза, и уже
  начатый ход Claude Code тоже останавливается: даётся пара минут довести
  действие до целостного состояния, потом инструменты закрыты до будильника.
- 📥 **Очередь входящих на время лимитов** (`tg_queue.py` + хук
  `UserPromptSubmit`) — пока окна сожжены, сообщение из чат-канала (Telegram и
  т.п.) не доходит до модели: оно ложится в очередь, отправителю отвечает сам
  хук («принял, вернусь в 16:03»), а разбирается очередь после подъёма. Без
  этого каждое новое сообщение будит сессию и добивает остаток окна, хотя
  человек в чате уверен, что его сообщения копятся.
- 🎨 **Пять оформлений** (v1.16.0) — классика, Phosphor (зелёный люминофор),
  Aurora (тёмное стекло), Slate (графит, тонкие линии), Blocks (крупные блоки).
  Шестерёнка → «Оформление»: карточки с превью, выбор запоминается в браузере,
  без внешних шрифтов и запросов — только системные гарнитуры. Всё — чистый CSS
  через атрибут `data-skin`, разметка и логика у всех оформлений одни.
- 🖥 **Страница вписана в окно** (v1.19.2) — шапка, консоль и карточки
  помещаются в окно без прокрутки страницы: консоль забирает остаток высоты,
  карточки аккаунтов идут в ряд по ширине окна. «−/+» в углу консоли меняют
  только шрифт консоли (запоминается, клик по проценту — 100%), размеры блоков
  при этом не прыгают.
- ⛶ **Только консоль** (v1.19.2) — кнопка ⛶ в углу консоли: консоль на весь
  экран (и на весь экран браузера, где он это умеет), аккаунты — в панели у
  нижнего края (по наведению, на телефоне — по язычку «Аккаунты»). Выход —
  та же кнопка или Esc, режим запоминается. Консоль сама прокручена к
  последним строкам и не дёргается, пока читаешь выше.
- 📱 **Смартфон** (v1.19.2) — шапка в два ряда, консоль ≈62% высоты экрана,
  линии из `─` подгоняются под ширину, «−/+» и ⛶ лежат внутри рамки консоли,
  панель аккаунтов в режиме «только консоль» — колонкой.
- ✋ **Подтверждение смены модели и effort** (v1.19.2) — нажатие на кнопку
  модели или на полосу effort спрашивает «точно?», чтобы не сменить их
  случайно при прокрутке (особенно на телефоне). Нажатие на уже выбранный
  уровень effort ничего не делает.
- 🎚 **Уровни effort по модели** — `/api/limits` отдаёт для каждой модели
  список поддерживаемых уровней (из каталога, зашитого в бинарник Claude Code;
  неизвестная модель не блокируется), а установка уровня, который модель не
  принимает, отклоняется с понятным текстом.
- ⏳ **Срок логина на карточке** (v1.17.0) — рядом с «Войти заново» чип
  «логин N дн»: сколько осталось до даты, после которой аккаунт отвалится с
  «Login expired». Дата берётся из `refreshTokenExpiresAt` в `credentials.json`
  (абсолютная, ≈28 дней от настоящего `/login`; обычное обновление токена её
  не продлевает). ≤3 дней — красный, ≤7 — жёлтый, меньше суток — часы, после
  срока — «истёк»; в подсказке — точная дата. Токены в `/api/limits` не
  попадают, наружу идёт только дата `login_expires`. Вписан во все пять
  оформлений.
- ➕ **Добавление и удаление аккаунтов из панели** (v1.19.0) — кнопка
  «+» в шапке рядом с шестерёнкой: ссылка входа → код со страницы → аккаунт
  сам встаёт в ротацию. Кнопка «Удалить» на карточке убирает аккаунт навсегда
  (профиль с токенами и все следы в снимке) — потерял доступ к аккаунту, и он
  больше не висит мёртвым грузом. Подтверждение — вводом слова «подтверждаю»,
  корзины и отката нет. Telegram сообщает об обоих действиях. Вписано во все
  пять оформлений, RU/EN.
- 🔄 **Обновления из панели** (v1.18.0) — раз в сутки панель спрашивает у GitHub,
  нет ли релиза новее, и показывает баннер «Вышла v1.18.1 — Обновить / Пропустить
  эту версию». В «⚙ Настройки» — переключатель **«Вручную / Автоматически»**
  (по умолчанию вручную): ручной ставит по кнопке, автоматический сам скачивает
  архив, проверяет, подменяет файлы и перезапускает службу. Перед заменой —
  бэкап, при сбое старта — автоматический откат. Подробности — в разделе
  «Обновления из панели». Вписано во все пять оформлений, RU/EN.
  Там же свёрнутая строка **«История изменений»** (v1.20.0): все версии с
  v1.0.0 — дата, заголовок и пара пунктов, новые сверху.
- 🔔 **Баннер состояния** вверху панели (RU/EN): «упёрлись в лимиты —
  переключаться некуда», «активный аккаунт забит — фоновые задачи стоят»,
  «на паузе, подъём в 16:03» с обратным отсчётом. В норме баннера нет.
- 📨 **Уведомления в Telegram** (опционально): переключение аккаунтов,
  «переключаться некуда», постановка паузы и подъём по будильнику — чтобы не
  сидеть в панели. Токен бота — из файла телеграм-канала Claude Code или
  прямо из `config.json`.
- 🧠 **Пул моделей** (шестерёнка в шапке) — отметь чекбоксом, какие модели
  показывать кнопками быстрого переключения на главной; клик по кнопке сразу
  меняет модель дефолтной сессии. Новая модель в пуле помечена бейджем
  «новая» первые 14 дней.
- ⏱ **Кольцо-таймер до сброса окна** — на карточке каждого аккаунта, рядом с
  почтой: цвет кольца сам показывает срочность (зелёный → жёлтый → красный по
  мере приближения сброса 5-часового окна).
- ⌨️ **Кнопки `/compact` и новая сессия** — прямо на карточке активного
  аккаунта, без переключения в терминал: сжать контекст или начать `/clear`
  одним кликом (та же инъекция в `screen`-сессию, что и у кнопок переключения
  модели).
- 🔐 Ничьи OAuth-токены никуда не улетают — всё живёт на твоём собственном
  сервере, под твоим root.
- 🧩 Один установочный скрипт, без веб-визардов и внешних зависимостей от
  чужой инфраструктуры.

## Требования

- Свой VDS/сервер (root-доступ), Ubuntu/Debian с `apt`.
- Установленный Claude Code (`npm i -g @anthropic-ai/claude-code`), команда
  `claude` должна быть в `PATH` (`install.sh` предупредит, если её нет).
- 2+ Pro/Max-аккаунта Claude, между которыми нужно переключаться.
- *(опционально)* домен с A-записью на сервер — для веб-панели по HTTPS
  вместо голого `127.0.0.1:8877`.

## Установка

```bash
git clone https://github.com/r38dark/cc-fleet.git
cd cc-fleet
sudo ./install.sh
```

Установщик спросит: имя `screen`-сессии, где живёт Claude Code, сколько
аккаунтов завести, порог авто-переключения, нужен ли nginx-домен с Basic
Auth, нужны ли уведомления в Telegram. Дальше сам:

1. поставит `python3-pyte python3-pexpect screen` (+ `nginx apache2-utils`,
   если выбран веб-домен),
2. скопирует `cc_limits.py`, `cc_update.py`, `cc_avail.py`, `limits_gate.py`, `pause_ctl.py` →
   `/opt/cc-limits`, `cc-switch` → `/usr/local/bin/cc-switch`,
3. заведёт N пустых слотов-профилей в `/root/.claude-profiles/accN`,
4. сгенерирует `config.json` со случайным `hook_token` (при повторном запуске
   — обновит существующий, не трогая токен и твои ключи),
5. поставит и запустит systemd-сервис,
6. поставит cron-будильник паузы (`/etc/cron.d/cc-limits-pause`, тик раз в
   минуту),
7. проверит, что сервис реально отвечает (health-check `/api/limits` и
   `/api/pause`),
8. *(опционально)* настроит nginx vhost + Basic Auth.

Без вопросов — для скриптов/CI:

```bash
CC_FLEET_YES=1 sudo -E ./install.sh
```

Все параметры берутся из переменных окружения `CC_FLEET_*` (см. шапку
`install.sh`) или из значений по умолчанию.

HTTPS после установки настраивается отдельно, вручную: если ставил nginx —
`certbot --nginx -d <домен>`.

## Как запустить сам Claude Code в screen-сессии

Сервис только мониторит/переключает — саму сессию поднимаешь стандартно:

```bash
screen -S claude -dm claude
```

(имя сессии должно совпадать с указанным в install.sh — по умолчанию
`claude`). Живая сессия подхватывает подмену токенов на лету, рестарт не
требуется.

## Онбординг аккаунтов

Двух способов достаточно, оба сохраняют аккаунт в
`/root/.claude-profiles/accN/`:

**Через веб-кнопку «Войти заново»** (панель `/cc/`, если ставил nginx) —
install.sh уже завёл N пустых слотов (`oauth_account.json: {}`), кнопка
стартует `claude auth login` в изолированном temp-HOME, отдаёт ссылку OAuth,
логинишься в браузере под нужным Claude-аккаунтом и вводишь код обратно на
странице.

**Вручную, если панель ещё не поднята:**

```bash
# в screen-сессии из предыдущего шага — там уже открыт claude
/login    # логинишься под нужным аккаунтом внутри TUI
```

затем в обычном шелле:

```bash
cc-switch save 1   # сохраняет ТЕКУЩУЮ живую сессию как профиль acc1
```

Повтори `/login` + `cc-switch save N` для каждого следующего аккаунта.
Проверить, что видит сервис: `cc-switch list`.

## Добавление и удаление аккаунтов (v1.19.0)

**Зачем это понадобилось.** Аккаунт может стать недоступным: потерян доступ к
почте или телефону, и подтвердить вход заново («Войти заново» просит
подтверждение в браузере) уже нельзя. Логин живёт ≈28 дней от настоящего
`/login` и не продлевается (см. чип «логин N дн» на карточке) — когда срок
выйдет, аккаунт начнёт падать с «Login expired», а перелогинить его нечем.
Мёртвый аккаунт остаётся в ротации: карточка с ошибкой, лишние запросы,
предупреждения. Раньше убрать его можно было только руками в файловой системе.
Теперь — из панели, а новый аккаунт так же добавляется без SSH.

### Удаление аккаунта навсегда

Кнопка **«Удалить»** на карточке → окно с красным предупреждением
**«Это безвозвратно»**. Кнопка **«Удалить навсегда»** неактивна, пока не введено
слово **«подтверждаю»** (в английском интерфейсе — `confirm`); регистр и
пробелы по краям не важны. Слово проверяет и страница, и сервер — запрос к API
без него ничего не удалит. Esc, «Отмена» и клик по фону закрывают окно, ничего
не сделав.

- **Что стирается:** папка профиля `/root/.claude-profiles/accN/` целиком (в ней
  токены), строки аккаунта в снимке, кэшах и служебном состоянии, отметка
  «активный».
  Корзины и отката нет: аккаунт пропадает и из ротации, и с экрана; вернуть его
  можно только добавив заново (новый вход через браузер).
- **Активный аккаунт** удалить можно: сначала живая сессия переводится на другой
  пригодный аккаунт (не Free, лучше с запасом лимита). Не нашлось, куда переводить, —
  удаление отказывается, ничего не стёрто.
- **Последний аккаунт** в ротации удалить нельзя.
- `cc-switch` после удаления профиль просто не видит.

### Добавление аккаунта

Кнопка **«+»** в шапке (рядом с шестерёнкой «Модели», подсказка «Добавить аккаунт») → окно:

1. почта аккаунта (необязательно — подставится на странице входа, чтобы не
   набирать заново) → **«Получить ссылку для входа»**;
2. открыть ссылку, войти в нужный аккаунт Claude, вставить код со страницы
   входа → **«Добавить в ротацию»**.

Через несколько секунд на экране новая карточка, аккаунт участвует в
авто-переключении — вручную ничего настраивать не нужно.

- Вход идёт в изолированном temp-HOME (как у «Войти заново»), живая сессия
  Claude Code не затрагивается.
- Новый профиль занимает первый пустой слот установщика, иначе следующий номер
  `accN`.
- Тот же аккаунт второй раз не добавится: «уже в ротации как accN».
- Free-аккаунт добавится, но в авто-переключении не участвует, пока не станет
  Pro (Telegram об этом предупредит).
- Брошенная попытка (ссылку получили, код не ввели) снимается сама примерно
  через 10 минут (проверка на каждом опросе лимитов) или при новой попытке.

### Telegram и API

Если настроен Telegram — по одному сообщению на каждое действие, например:
`🗑 Claude: аккаунт acc3 (…) удалён из ротации навсегда — профиль и токены
стёрты, вернуть нельзя. В ротации осталось: 2 (acc1, acc2).` и
`➕ Claude: аккаунт acc4 (…, PRO) добавлен в ротацию. Теперь в ротации: 3
(acc1, acc2, acc4).`

API (все с `?token=<hook_token>`, тело — JSON; необязательное поле `lang`
`ru`/`en` выбирает язык текста в ответе):

| Запрос | Что делает |
|---|---|
| `POST /api/account/delete` `{"account":"acc3","confirm":"подтверждаю"}` | удалить аккаунт навсегда; без верного слова — `ok:false`, ничего не удалено |
| `POST /api/account/add/start` `{"email":""}` | начать вход → `{url, slot}` |
| `POST /api/account/add/submit` `{"slot":"acc4","code":"…"}` | завершить вход кодом со страницы → аккаунт в ротации |

## Гейт для фоновых задач и пауза по лимитам (v1.2.0)

Ротация решает вопрос «на каком аккаунте работать». Остаются два случая,
которые она не закрывает: фоновые (headless) задачи, которые молча съедают
окно активного аккаунта, и момент, когда **все** аккаунты выше порога.

**Гейт.** `limits_gate.py` — короткий скрипт с кодом возврата: `10` — сейчас
запускаться нельзя, `0` — можно. Ставится в начало любого своего cron-скрипта:

```bash
python3 /opt/cc-limits/limits_gate.py || exit 0   # rc=10 — просто не стартуем
```

Блокирует в двух случаях: активный аккаунт выше порога (ждём, пока балансер
уйдёт на свежий) или все аккаунты выше порога (переключаться некуда). Если
`snapshot.json` пропал или протух — гейт **пропускает** (fail-open): лучше
лишний прогон, чем молча стоящий демон.

**Пауза.** `pause_ctl.py` держит состояние в `pause_state.json` рядом со
снапшотом, а будит его системный cron (`/etc/cron.d/cc-limits-pause`, тик раз
в минуту) — поэтому пауза переживает перезапуск сессии, `/clear` и ребут.

```bash
python3 /opt/cc-limits/pause_ctl.py set --reason "все аккаунты выше порога" \
        --note "что не доделано — увижу при подъёме"
python3 /opt/cc-limits/pause_ctl.py status      # что сейчас + вердикт гейта
python3 /opt/cc-limits/pause_ctl.py clear       # снять руками
```

Время подъёма берётся из ближайшего сброса 5-часового окна среди всех
аккаунтов (+3 минуты, окно отпускает не мгновенно). На каждом тике cron
перепроверяет гейт: красный — молча переносит будильник на новое окно и растит
счётчик перепроверок, зелёный — снимает паузу и «печатает» в `screen`-сессию
Claude Code сообщение о подъёме (`screen -X stuff`), чтобы работа продолжилась
сама. Текст сообщения переопределяется ключом `pause_wake_message` в
`config.json`; он **строго ASCII** — `screen`, поднятый без `-U`, принимает
не-ASCII побайтовым мусором и швыряет его прямо во ввод сессии.

Всё это видно в панели: `GET /api/pause` отдаёт то же состояние, которое
считает `pause_ctl`, — баннер, гейт и будильник смотрят в одни и те же файлы,
поэтому страница не может обещать одно, а фоновые задачи вести себя иначе.

Если настроен Telegram (см. ниже), о постановке паузы и о подъёме приходит
уведомление — в панель для этого заглядывать не нужно. Молчаливые переносы
будильника (окно ещё не отпустило) в бот не идут, иначе он писал бы каждые
несколько минут; они видны в `pause_wake.log` и в счётчике перепроверок.
Отключается ключом `"pause_notify": false` в `config.json`.

## Очередь входящих на время лимитов (v1.3.0)

У чата с Claude Code нет очереди: каждое входящее сообщение будит сессию, и та
немедленно берётся за работу — в том числе когда окна уже сожжены и работать
нечем. Человек при этом обычно уверен, что его сообщения копятся и будут
разобраны позже. Эта версия делает такое поведение настоящим.

Работает так: хук `UserPromptSubmit` (`hooks/queue_on_limits.py`) смотрит на
входящий промпт **до** обращения к модели. Если это сообщение из чат-канала
(`<channel …>`) и гейт «красный» — промпт блокируется (токены не тратятся),
текст ложится в `tg_queue.jsonl`, отправителю уходит подтверждение через Bot
API, а пауза поднимается автоматически, чтобы cron-будильник разбудил сессию
на ближайшем сбросе окна. В сообщении о подъёме появляется строка «в очереди N
сообщений — разбери их первым делом».

```bash
python3 /opt/cc-limits/tg_queue.py count   # сколько ждёт
python3 /opt/cc-limits/tg_queue.py list    # посмотреть, не помечая
python3 /opt/cc-limits/tg_queue.py take    # выдать и пометить разобранными
python3 /opt/cc-limits/tg_queue.py clear   # аварийный сброс очереди
```

Блокируется только состояние «работать реально негде»: все аккаунты выше
порога либо пауза уже стоит. Если активный аккаунт сожжён, но свободный есть,
сообщение проходит как обычно — балансер переключится сам. Обычный ввод в
терминале (без `<channel>`-тега) хук не трогает вообще, любая ошибка внутри
хука — тоже пропуск (fail-open): очередь не должна становиться причиной, по
которой сообщения теряются.

Текст подтверждения переопределяется ключом `queue_ack_message` в
`config.json` (плейсхолдеры `{n}`, `{line}`, `{when}`), отключается ключом
`"queue_ack": false` — тогда сообщение просто молча ляжет в очередь.

Хук подключается вопросом установщика (правит `hooks.UserPromptSubmit` в
`settings.json` Claude Code, делая бэкап рядом) либо руками:

```json
{ "hooks": { "UserPromptSubmit": [ { "hooks": [ { "type": "command",
  "command": "CC_LIMITS_DIR=/opt/cc-limits /usr/bin/python3 /opt/cc-limits/hooks/queue_on_limits.py" } ] } ] } }
```

⚠️ Claude Code читает `settings.json` при старте — после подключения хука
сессию надо перезапустить, иначе он не будет вызываться.

## Кнопка отключения паузы и стоп-кран инструментов (v1.15.0)

**Пауза ставится только по 5-часовому окну.** Уровень «переключаться некуда»
(`hard`) — это все аккаунты выше порога именно сессионного окна. Недельный
потолок (`weekly_cap`) паузу не ставит и будильник не держит: он по-прежнему
работает в балансере (аккаунт у потолка недели не выбирается), но ни живую
сессию, ни фоновые задачи (гейт `limits_gate.py`, с v1.15.1) из-за него не
останавливает.

**Исключение — опция «Пауза на недельном потолке» (v1.21.0).** Активный
аккаунт дошёл до `weekly_cap` (99%), а пригодных для переключения нет —
уровень `week`: пауза встаёт так же, с тем же стоп-краном и кнопкой
«Отключить паузу». Будильник проверяет её каждую минуту и снимает, как только
есть куда работать (освободился другой аккаунт или сбросилась неделя). Опция
выключена (`"weekly_pause": false`, по умолчанию) — уровень `weekrisk`: паузы
нет, баннер и Telegram предупреждают, что заполнение до 100% балансер не
остановит.

**Кнопка.** Пока стоит пауза (или все окна забиты), в баннере панели есть
кнопка «Отключить паузу». Нажал — пауза снята, сессию сразу будит сообщение
«работа сверх порога разрешена», очередь входящих больше не копится, хук
инструментов пропускает всё. Баннер становится зелёным «Пауза отключена
вручную» с кнопкой «Включить паузу»: она возвращает паузу обратно — если окна
всё ещё забиты, пауза встаёт сразу с будильником на ближайший сброс. Не нажал
«Включить» — cron сам вернёт паузу в рабочий режим, как только окно отпустит
(в логе: «пауза снова включена: окно отпустило»), так что забытая кнопка не
оставит паузу выключенной навсегда. То же из консоли:

```bash
python3 /opt/cc-limits/pause_ctl.py off --by "я"   # отключить паузу
python3 /opt/cc-limits/pause_ctl.py on  --by "я"   # включить обратно
```

Панель дёргает то же самое через `POST /api/pause?token=<hook_token>` с телом
`{"action": "off"}` или `{"action": "on"}`.

**Стоп-кран инструментов.** Без него пауза глушит только новые входящие, а
уже начатый ход идёт дальше и добивает окно, пока сам не закончится. Хук
`PreToolUse` (`hooks/pause_tool_gate.py`) это закрывает: пауза активна — на
первый вызов инструмента Claude получает отказ с инструкцией «новых шагов не
начинать, довести начатое до целостного состояния и записать, что осталось»,
дальше 120 секунд на это, потом любой инструмент — отказ до будильника. Если
все аккаунты выше порога, а паузы ещё нет, хук ставит её сам. Всегда
пропускаются: memory проектов, `settings.json` и хуки Claude Code, команды
`pause_ctl`/`tg_queue` (аварийный выход — `pause_ctl.py off` или `clear`).
Пауза отключена кнопкой — пропускается всё; любая ошибка внутри хука — тоже
пропуск.

Подключается вопросом установщика (правит `hooks.PreToolUse` в
`settings.json`, делая бэкап рядом) либо руками:

```json
{ "hooks": { "PreToolUse": [ { "matcher": "*", "hooks": [ { "type": "command",
  "command": "CC_LIMITS_DIR=/opt/cc-limits /usr/bin/python3 /opt/cc-limits/hooks/pause_tool_gate.py" } ] } ] } }
```

## Обновления из панели (v1.18.0)

Раз в сутки (и по кнопке «Проверить» в «⚙ Настройки → Обновления») панель делает
**один** запрос `GET https://api.github.com/repos/r38dark/cc-fleet/releases/latest`
— без токена, без отправки чего-либо о тебе (с `If-None-Match`, так что чаще всего
GitHub отвечает «304, без изменений»). Нашёлся релиз новее — вверху панели
баннер с описанием релиза и кнопками, а если настроен Telegram — одно сообщение
на версию.

| Режим | Что происходит |
|---|---|
| **Вручную** (по умолчанию) | баннер + кнопка **Обновить**; **Пропустить эту версию** прячет баннер, пока не выйдет следующая (в настройках можно всё равно поставить пропущенную) |
| **Автоматически** | панель сама ставит найденный релиз; сообщение в Telegram — «обновлён» или «не удалось» |

Как идёт обновление (баннер показывает этапы):

1. архив качается **только с GitHub** (проверяется каждый редирект, лимит 30 МБ);
   если GitHub отдал `sha256` ассета — сумма сверяется;
2. архив распаковывается во временную папку без символических ссылок и путей
   наружу; список заменяемых файлов берётся из `update_manifest.json` релиза,
   писать можно только в `/opt/cc-limits` (и `cc-switch` в `/usr/local/bin`);
   каждый `.py` компилируется, `VERSION` должна совпасть с версией релиза;
3. **бэкап** заменяемых файлов в `/opt/cc-limits/update_backup/` (хранятся
   последние 3), затем файлы подменяются и служба перезапускается;
4. новая версия за ≈20 секунд работы сама подтверждает запуск. Не подтвердила
   за 2 минуты (упала, зациклилась) — отдельный systemd-юнит-сторож
   **возвращает прежние файлы** и перезапускает службу; в баннере будет
   «не удалось, прежняя версия возвращена». Версию, которая не поднялась,
   автоматический режим сам повторно не ставит (вручную — кнопка «Повторить»);
5. открытые вкладки панели после подтверждения сами перезагружаются на новую
   версию (v1.21.1) — кроме момента, когда открыт диалог аккаунта, в поле
   недописанный текст или включён полноэкранный режим: тогда сразу после.

Что важно знать:

- **Это исполнение чужого кода от root.** Обновление ставит то, что опубликовано
  в релизе репозитория. Если не хочешь — оставь «Вручную» (баннер кладёт перед
  глазами описание релиза и ссылку на страницу) или выключи проверку совсем:
  галка «Проверять новые версии раз в сутки» в настройках, либо
  `"update_check": false` в `config.json`.
- Нужен systemd и установка через `install.sh` (юнит
  `/etc/systemd/system/<служба>.service`, имя службы лежит в `config.json` как
  `service_name`). Иначе баннер только сообщает о новой версии и говорит
  обновиться вручную.
- Если релиз меняет саму установку (юнит, nginx, хуки), автообновление его не
  ставит и просит один раз запустить `sudo ./install.sh` из архива релиза.
- **Установкам ≤ v1.17.0 нужен один ручной шаг:** `git pull && sudo ./install.sh`
  (в них ещё нет самого обновлятора). Дальше — из панели.
- Ключи `config.json`: `update_mode` (`manual`/`auto`), `update_check`
  (`true`/`false`), `update_repo` (по умолчанию `r38dark/cc-fleet`, нужен
  форкам), `service_name`.
- API: `GET /api/update` (состояние), `POST /api/update/check|apply|skip|ack`.
- **История изменений** (v1.20.0) — строка-спойлер в «⚙ Настройки →
  Обновления», по умолчанию свёрнута: версия, дата, заголовок и до трёх
  пунктов, новые сверху, на языке интерфейса. Данные — `CHANGELOG.json` в
  `/opt/cc-limits/` (ставит `install.sh`, обновляет обновлятор, отдаёт
  `GET /api/changelog`). Каждый релиз добавляет в него свою запись.

## Обновление с предыдущей версии

```bash
cd cc-fleet && git pull
sudo ./install.sh          # ответы можно оставить прежними
```

Повторный запуск идемпотентен: `hook_token` и уже настроенные ключи
`config.json` сохраняются, профили аккаунтов не трогаются. Обновятся файлы в
`/opt/cc-limits`, systemd-unit, cron-будильник и nginx-конфиг (если выбирал
nginx). Если ставить установщик повторно не хочется — достаточно скопировать
`cc_limits.py`, `cc_update.py`, `cc_avail.py`, `limits_gate.py`, `pause_ctl.py`, `tg_queue.py`,
`hooks/queue_on_limits.py` и `hooks/pause_tool_gate.py` в `/opt/cc-limits`, положить cron-строку из
`install.sh` и перезапустить сервис.

## Telegram-уведомления (опционально)

Что приходит в бот:

- авто-переключение аккаунта (и ручное, и сделанное `cc-switch` из консоли);
- «переключаться некуда» — все аккаунты выше порога; на недельном потолке —
  честно: пауза или «балансер не остановит заполнение до 100%» (v1.21.0);
- неделя аккаунта дошла до потолка 99% — одно сообщение на аккаунт за неделю,
  активный он или нет (v1.21.0);
- **пауза по лимитам поставлена** (до какого времени, проценты окон, что
  осталось незакрытым) и **пауза снята будильником** (сколько простояли,
  сколько раз будильник переносился) — v1.2.1;
- перелогин аккаунта через веб-кнопку;
- аккаунт **добавлен в ротацию** или **удалён навсегда** (v1.19.0);
- слёт аккаунта с Pro на Free и возврат обратно.

Кому слать — ключ `chat_id` в `config.json` (спрашивает `install.sh`). Токен
бота берётся из двух мест, в таком порядке:

1. `/root/.claude/channels/telegram/.env` (`TELEGRAM_BOT_TOKEN=...`) — файл
   официального Telegram-канала Claude Code;
2. ключ `bot_token` в самом `config.json` — если канал не настроен и заводить
   его не хочется (обычный токен от @BotFather).

Без `chat_id` уведомления тихо пропускаются, сервис работает как обычно. Если
`chat_id` задан, а токена нет ни там ни там — сервис пишет об этом в свой лог
(`journalctl -u cc-limits`), чтобы молчание бота не выглядело загадкой.
Уведомления про паузу отключаются отдельно: `"pause_notify": false` в
`config.json` (остальные при этом продолжают ходить).

## Без nginx / без домена

Сервис слушает только `127.0.0.1:<port>`. Подключай свой reverse-proxy:

- Главная страница (`GET /`) отдаётся, только если прокси прислал заголовок
  `X-Auth-User` (обычно из Basic Auth) — так панель не смотрит наружу голой.
- Все API (`/api/...`) можно дёргать и без этого заголовка — с
  `?token=<hook_token>` в query. Панель сама так и ходит (браузер не всегда
  пробрасывает Basic Auth в `fetch()`), поэтому обычно нужны ДВЕ location у
  прокси: одна с Basic Auth → корень сервиса (`X-Auth-User` от прокси),
  вторая без Auth → `/api/` (доступ только по знанию `hook_token`). Пример —
  в блоке nginx, который генерирует `install.sh`.

## Коды ошибок

Что означает `429`/`400`/`403` на карточке аккаунта, когда каждый из них
реально возникает и что с ним делать — [ERRORS.md](ERRORS.md).

## Что НЕ входит в этот пакет

- Личный дашборд агентов/супервизора — отдельная надстройка поверх Claude
  Code, к ротации аккаунтов не относится, тут её нет.
- Функция «escalation» (мониторинг фоновых cost-эскалаций) — вырезана,
  специфична для другой системы.
- HTTPS/certbot — шаг после `install.sh`, вручную.

  - веб-страница больше не опрашивает Anthropic сама, только читает снапшот;
  - баннер пишет, кто освободится первым и что его держит, в чипах есть

  кнопка радостно писала «вернул в ротацию», хотя авто-переключение всё

  `plan ok + error` — отдельное честное сообщение без ложного «успеха».

  **Важно про холодный старт:** якорь пишется только внутри `/api/recheck`,

  момента единственная страховка — мгновенный Telegram-алерт о реальном
  обвале Pro→Free (см. выше), он работает независимо от таймера.
